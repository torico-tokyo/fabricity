# Documentation generation.
#
# Lower bounds only, no upper bounds. The previous pins were the 2016 set
# inherited from upstream Fabric3 and could not be installed-and-imported at
# all on the Python versions this suite targets: Sphinx 1.3.4 is broken by its
# own source on Python 3.11+ (sphinx/domains/cpp.py does
# `re.compile(r'\s+(?u)')`, and an inline global flag that is not at the start
# of the pattern became an error in 3.11), and no jinja2/markupsafe
# combination worked around it.
#
# The bounds below are the oldest versions actually verified to build both
# sites, not guesses:
#   * invoke >= 2.2 -- 2.0/2.1 import `imp`, removed in Python 3.12.
#   * invocations >= 4.0.2 -- earlier releases import `pip` without depending
#     on it, so they fail in a venv built without pip. 4.0.2 declares it.
#   * releases >= 2.0 -- the 1.x line is written against Sphinx 1.x.
#   * Sphinx >= 7.0 / alabaster >= 0.7.13 -- oldest pair verified here.
#
# Verified on Python 3.13 at both ends of those ranges (Sphinx 7.0.1 +
# releases 2.0.1 + invoke 2.2.0 + invocations 4.0.2 + alabaster 0.7.13, and
# Sphinx 9.1.0 + releases 2.1.1 + invoke 3.0.3 + invocations 4.0.2 +
# alabaster 1.0.0). Both build the whole `.travis.yml` sequence -- `invoke
# www`, `invoke docs -o -W`, `invoke www -c -o -W` -- with zero warnings.
# Note that Sphinx 9 requires Python >= 3.12, so a 3.9-3.11 checkout resolves
# to an older Sphinx within these bounds; that is intended.
#
# semantic_version, six, wheel and twine used to be listed here. They are all
# either declared by invocations (which pulls in twine/wheel/tabulate/pip) or
# by the package itself (six, via install_requires), and the old `==` pins
# actively conflicted with those.
Sphinx>=7.0
releases>=2.0
invoke>=2.2
invocations>=4.0.2
alabaster>=0.7.13
